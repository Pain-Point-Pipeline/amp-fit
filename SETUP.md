# Setup, once

1. Publish the skill (once per machine; again after editing it). The canonical copy is `skills/amp-fit/` here; the published copy is the Amp personal skills repository, cloned at `../user-skills` (`amp git-setup` once for credentials, then `amp clone user-skills`). Republish: `rm -rf ../user-skills/amp-fit && cp -r skills/amp-fit ../user-skills/amp-fit && git -C ../user-skills add -A && git -C ../user-skills commit -m "amp-fit skill" && git -C ../user-skills push`. Personal skills load everywhere Amp runs, Orbs included. Do not also install it locally: a local copy masks the published one and drifts.
2. Per private repo, access for the Orb's GitHub identity, which is `ampfit2-lab`: `gh api -X PUT repos/<owner>/<repo>/collaborators/ampfit2-lab -f permission=admin` (Daniel's choice; `push` is the minimum a pass needs), then accept the invitation in the browser signed in as ampfit2-lab (`github.com/<owner>/<repo>/invitations`); the fine-grained ampfit2-lab token in `gh` on this machine cannot accept invitations.
3. Per repo, the project: `amp projects create <owner>/<repo> --personal --ship-behavior custom --custom-ship-prompt-file skills/amp-fit/ship.md --json` (add `--name <x>` when the repo name is already a project). "Amp could not access this GitHub repository" means step 2 is incomplete or the Amp GitHub App is not installed on the owning account for that repository (ampcode.com/settings, then GitHub). After editing `ship.md`, update each project's stored copy of it: `amp projects update <project> --custom-ship-prompt-file skills/amp-fit/ship.md`.
4. Smoke test, not a pass, no row: `amp -ox "Smoke test, not a pass: list this repository's top-level files and the names of the skills available to you, then stop without changing anything." --mode low --project <owner>/<repo> --visibility private`, then `amp threads markdown <T>`. Pass = the repo's files and `amp-fit` among the skills. Files but no skill: prepend the body of SKILL.md to that pass's launch line and note it in the postmortem. No files: fix step 2 or 3, or use step 5.
5. Local fallback: `git clone` the repo under `~/Documents/Repos/`, `cd` in, `amp --mode high`, type the launch line.
