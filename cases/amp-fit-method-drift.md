## The actual responsibility

Carry the intended product outcome from the owner's work history into the active
method, implementation choices, and acceptance evidence. Diagnose and correct
substitutions that leave the original problem untouched. This is broader than
fixing the latest broken test, and it is grounded in this project's actual work.

This occurrence requires a coherent active assignment that preserves the real
work input, permits scripts and adaptive Amp labor, assigns human decisions
explicitly, and distinguishes supporting lab checks from proof of usefulness.
The owner should not have to restate those decisions every time the agent
encounters an easier nearby engineering task.

## Diagnosis

The old active path began with “understood workflow packet”; the packet already
contained the job. A comparer export then became the checkable positive result.
Separate phase records, evaluator calibration, and publication calibration could
all advance while discovery and actual recurring work were never exercised.

The current agent reproduced that causal pattern by ranking available error logs
and tests above the owner's unresolved objective. More careful repair work would
not have corrected that selection. The
[selection record](../workflow-selection-error.md) documents the error without
attributing it to an instruction or treating it as a method success.

## Correction applied locally

- `METHOD.md` is a reusable agent assignment with explicit component purposes
  and evidence limits. It starts from the whole trail and owner objective, and
  leaves task steps and tools open to the actual work.
- `AGENTS.md`, `OPERATE.md`, and `README.md` point to that assignment and this
  real case. This corrects the first files an agent will read, rather than adding
  a disconnected design note.
- `DESIGN.md` identifies its six-phase contract as the frozen D1 lab. `DEFERRED.md`
  no longer describes another native CAL run as the universal next phase.
- Scripts remain valid interventions; the actual completed work is evaluated.
  Human decisions and observed review burden remain part of the arrangement.
- Side repairs are preserved outside the active diff. No lab code, historical
  result, capability flag, live schedule, or external product was changed to make
  this correction appear proven.

## Acceptance and remaining human role

This local correction can be checked for consistency: the entry instructions must
lead to the real responsibility; the D1 contracts must retain their calibration
meaning; source links must resolve; permission and human-decision boundaries must
remain intact. Those are checks of the correction, not proof that the broader
product now works.

The first work selection failed and Daniel intervened. A review after that
intervention cannot be counted as independent discovery or a second held-out
occurrence. Whether this guidance reduces future redirection and produces useful
work must be observed on a later actual pass, including human review effort.
Product usefulness and any future activation remain human decisions. No such
decision is inferred from a clean document review.

Further code should follow an actual limitation encountered while doing this
work. A new general controller, taxonomy, score, or fixture is not required to
start executing the assignment with an agent's ordinary tools.
